# OctoAcme — Project Management Processes (Overview)

This repository contains the OctoAcme program management process docs. These living documents describe how we initiate, plan, execute, release, and continuously improve work. Use the documents in this folder as the single source of truth for project processes and the Copilot Space context.

## Purpose
Provide a concise summary of OctoAcme's operating rhythms and key artifacts so team members can quickly understand how we run projects.

## Key Principles
- Customer-first: prioritize customer value and usability.
- Iterative delivery: deliver small, testable increments.
- Clear ownership: each project has a named PM and Product Lead.
- Data-informed decisions: measure outcomes and iterate.
- Psychological safety: encourage feedback and learning.

## Typical Cadence
- Daily standups for delivery teams (15 min)
- Weekly delivery sync and PM/PdM alignment
- Demos at the end of each sprint or milestone
- Monthly stakeholder updates (or as-needed)

## How to use these docs
- Add process updates via the ".github/ISSUE_TEMPLATE/Add Content to Process Docs" template.
- Propose content changes as issues and link the update PR to the issue for review/approval.
- Keep the project one-pager and release notes in the project repository as the source of truth.

## Quick checklist for new projects
- One-pager completed and reviewed
- Backlog prioritized and estimated
- CI and linting configured
- Release plan and DoD documented
- Risk register started
